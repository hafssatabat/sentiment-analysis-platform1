
# Guide de contribution

## 1. Objectif

Ce document définit les règles de collaboration pour le projet
sentiment-analysis-platform.

## 2. Convention de nommage des branches

Chaque membre doit créer une branche depuis main.

Exemples :
- feature/SAP-24-dataset-collection
- feature/SAP-38-api-contract
- docs/SAP-21-branching-rules
- docs/SAP-23-project-documentation

## 3. Convention des commits

Chaque commit doit contenir le numéro de la tâche Jira
et une description claire.

Exemples :
- SAP-21: add pull request template
- SAP-24: add data loading script
- SAP-38: add API skeleton

## 4. Pull Requests

Chaque membre doit :
1. Développer sur sa propre branche.
2. Publier sa branche sur GitHub.
3. Créer une Pull Request vers main.
4. Ajouter une description et la référence Jira.
5. Demander une revue de code à un autre membre.

## 5. Revue de code

Avant la fusion :
- Vérifier la lisibilité du code.
- Vérifier le respect de la structure du projet.
- Vérifier l'absence de fichiers sensibles.
- Obtenir l'approbation d'un autre membre.

## 6. Fusion

Après validation, la Pull Request peut être fusionnée
dans la branche principale main.
